# Flow Desk 0.2

Local cross-desktop adapter: VirtualDesktopAccessor is now bundled inside the project, with its MIT license, release-matching source, pinned reference source and binary hash under `third_party/VirtualDesktopAccessor/`. There are no runtime downloads. When the public Windows move API denies an explicitly selected window, Flow Desk uses the local isolated `FlowDesk.DesktopWorker.exe` and `native/VirtualDesktopAccessor.dll`. The picker waits asynchronously so this operation does not block its UI.

Before moving, the helper validates HWND/PID/creation time and session, probes desktop APIs, and checks desktop GUIDs against the public API. Original desktop GUID/index is included in the attachment recovery journal. Detach and guardian restoration attempt to return the window to that GUID (including after desktop reorder); if the original desktop was removed, the restored window stays usable and a local recovery log records the failure. No desktop is created/deleted/switched, and no foreign process is terminated.

Verified on Windows 26H2 build 26300.9711 with four existing desktops: a separate-process disposable window was moved to another desktop, imported via the internal-API fallback, attached, detached, and returned to its original desktop GUID. Previous model/UI/launcher tests also pass. Compatibility with later Windows updates and protected/elevated applications is not guaranteed. See `third_party/VirtualDesktopAccessor/README.flowdesk.md` for provenance and worker cleanup behavior.

Empty workspace update: a zero-tab panel hides its native TabControl entirely instead of letting its default white surface cover the empty state. The dark empty state shows a vector workspace icon and **Add window / Run app** buttons. The visible tab strip routes blank-area mouse presses directly to the workspace drag controller, rather than relying on hit-test forwarding through intermediate child windows. Regression coverage captures the empty screen, checks the dark background and foreground ordering, and verifies that a blank-header mouse press begins capture for dragging.

Explicit workspace saving: new workspaces are temporary. Only **☰ → Workspaces → Save workspace…** opts a workspace into persistence. Closed temporary workspaces disappear from the menu and are excluded from the saved session. Saved workspaces remain available and may reconnect uniquely matched live windows when opened. Window names without a linked live window no longer create `(reconnect)` tabs: an empty panel shows an Add window / Run app hint instead. Old automatic history is preserved once in `%LOCALAPPDATA%\FlowDesk\legacy-workspaces.xml` and removed from the normal menu. Regression tests verify no placeholder tabs, exclusion of temporary layouts from disk and cleanup after close.

Application launching and other desktops:

- **☰ → Run app…** searches current-user/shared Start menu shortcuts and registered Windows packaged apps. **Browse .exe / shortcut…** launches a selected local executable or `.lnk`.
- A unique new window matching the launched executable/process is attached in Aligned mode after three stable observations. Existing windows, ambiguous windows and unidentified packaged-app processes are not attached arbitrarily. Use **Choose running window…** if an app reuses an existing instance or the launch cannot be correlated. Closing the launch dialog never terminates the started app.
- **☰ → Add window… → Include windows from other virtual desktops** reveals otherwise-hidden desktop windows, labelled in the Desktop column. Explicit selection requests a move through the public Windows virtual-desktop API. Windows may deny moving another process's window; in that case the dialog gives the exact reason and asks the user to move it with Task View, then Refresh. There is no undocumented desktop API or simulated keypress fallback. A still-cloaked window is rejected before attachment.
- Physical monitors on the current virtual desktop remain included by default.

Verified on this machine: 164 catalog entries including 45 packaged Windows apps; actual `.lnk` target resolution, process launch and native-window discovery; existing/ambiguous/unidentified window matching rejection; all-desktop enumeration includes current-desktop windows. Cross-virtual-desktop move success is not certified; failure remains explicit and recoverable. Packaged apps without a reliable executable/process match require manual window selection.

Touchpad/shell return update: out-of-context WinEvent listeners observe foreground changes, task-switch completion and cloak/uncloak notifications. They coalesce a UI-thread refresh of frame styles, DWM border appearance, tab viewport and managed geometry without forcing focus. If the shell activates an attached inactive application's window, the corresponding tab is selected without another focus request. Cloaked workspaces do not keep moving/showing external windows on another virtual desktop. Hooks are removed on shutdown. No touchpad gesture or global shortcut is intercepted.

Regression injects an uncloak notification after introducing stale frame bits and verifies they are repaired without a tab click. Actual hardware swipe remains unverified. References: [WinEvent hooks](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook), [event constants](https://learn.microsoft.com/en-us/windows/win32/winauto/event-constants).

Classic-frame/activation fix: workspace windows now use the actual `FormBorderStyle.None` styles without adding `WS_THICKFRAME`, caption or system-menu frame styles back in and without overriding non-client size calculations. Moving/resizing is handled through capture and the custom edge/header hit regions. Regression tests inspect native style bits through minimize/maximize/restore and verify resize anchoring/minimum size and movement across negative monitor coordinates. Cross-process `AttachThreadInput` was removed from tab focus handling so Flow Desk no longer joins its UI input queue to another application's queue. Aligned tab activation uses normal foreground activation; experimental embedded controls may require a direct mouse click to focus their editor.

Startup/window-control fix: only the last active saved workspace opens on a normal cold start. Other layouts remain in the Workspaces menu. Opening an already-open saved layout activates its existing window instead of duplicating it. The legacy session fallback selects one layout with tabs rather than reopening every historical/test workspace. Explicit later launches/tray clicks still create a new workspace as requested.

The frame rendering suppression was narrowed: Flow Desk no longer disables DWM non-client rendering or swallows native non-client paint/activation messages. Only the documented Windows 11 border-color suppression remains. A regression starts with ten saved layouts, verifies exactly one enabled window, then sends normal Windows minimize/restore/maximize/close commands and verifies each result.

Hidden-native-header fix: after tabs or font/DPI metrics change, the content crop is recalculated from `TCM_ADJUSTRECT` instead of an initial cached rectangle. The underlying TabControl is restricted to its content region; native header hit-testing and mouse selection are blocked. Only the visible custom tab strip selects tabs. Regression coverage changes metrics and adds tabs after initial layout, then verifies both geometry and exclusion of the hidden header from its input region.

Borderless workspace update: the Windows caption/title row is hidden. **☰ → Minimize window / Maximize window (Restore window) / Full screen (F11) / Close workspace / Exit Flow Desk** provides window controls. Drag the empty area to the right of the tabs to move the workspace; its thin perimeter still resizes. Maximizing uses the monitor's working area, keeping the taskbar accessible. Full screen uses the entire monitor. Both restore the prior normal bounds. The workspace name remains in the taskbar/Alt+Tab title. Only the Flow Desk title row is hidden; attached applications retain their own native controls.

Regression coverage verifies caption removal, resize/caption hit-test regions, menu availability, taskbar-aware maximization, and exact normal/fullscreen restore bounds.

Compact header update: application functions are inside the **☰** menu at the beginning of each panel's tab row. There is no separate toolbar. The row is 24 logical pixels high; tab labels are bounded to 185 pixels and truncate long titles. Mouse wheel over the strip scrolls overflowing tabs. All previous workspace, add, split, expand and restore actions remain in the menu.

Tab-switching changes: prepare hidden window bounds before revealing it without activation, reveal the incoming tab before hiding the outgoing tab, respect a stable application minimum-size result instead of repeatedly resizing it, and require movement past the drag threshold before starting a tab drag. No Windows animation settings are modified. Regression tests cover 20 stable tab-content selections and 20 native hide/show cycles, plus constrained-resize reconciliation; this is not a guarantee about every third-party application's own animation/rendering.

The application is now Flow Desk. Start menu: **Flow Desk**. Main executable: `dist/FlowDesk.exe`.

- Closing workspace windows detaches their apps and keeps Flow Desk running in the notification area.
- Left-click the tray logo, or launch Flow Desk again from Start: create a new workspace on the monitor containing the pointer, then open the Add window picker.
- Right-click the tray logo → **Exit Flow Desk** to stop the background application and detach remaining windows.
- Automatic startup is installed for the current user using `Startup\Flow Desk.lnk`, with the `--background` argument. It starts only the tray icon; repeated background launches create no workspace. Normal Start-menu/tray clicks still open a workspace.
- Settings are stored in `%LOCALAPPDATA%\FlowDesk\session.xml`. Existing current settings are retained during updates.

Single-instance activation uses an AutoReset event restricted to the current Windows user's SID. The secondary launcher signals the existing UI thread and exits. It grants foreground activation only to the existing process with the same executable path; Windows ultimately controls foreground permission. See [Microsoft's foreground-window rules](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow).

Verified: actual second launch exited, the existing PID remained 23720, saved workspace count changed from 2 to 3, and the new title became `Flow Desk · Workspace 3`. Start shortcut exists and points to the new executable. Multi-monitor/multi-virtual-desktop placement still needs user hardware confirmation. Existing model tests and menu lifecycle regression pass.

Antivirus exclusions were not changed. No security software, protection settings, or detection bypass was modified.
